# Material 3 adoption ledger for memox-v8 (spec v2.6.1)

This is the project-specific external conflict ledger that spec §11 asks for. It classifies every decision of the canonical spec copy (`docs/shared/design/m3-shared-widget-spec-v2.6.1.md`, status REVIEW CANDIDATE, never edited) against what memox-v8 has approved. Spec rules are inputs. They bind the project only where this ledger says `ADOPT`.

## Precedence

1. Approved project decisions: ADRs, `PRODUCT.md`, owner rulings recorded in merged plans, PRs and screen detail files.
2. `design/tokens.json`, `design/app_tokens.json`, `DESIGN.md` and the `flutter-theme-design` contracts.
3. Pinned SDK 3.47.5 behaviour.
4. Spec v2.6.1.
5. Conventions.

The higher source wins. A fact in a lower source never changes a higher one.

## Classes

| Class | Meaning |
|---|---|
| `ADOPT` | The spec rule binds the project. It is built or enforced by a later task. |
| `ALREADY_COMPLIANT` | The repo already satisfies it. The evidence is cited. |
| `CONFLICT` | A higher source disagrees. Resolution is `KEEP_EXISTING` until the owner signs a change. |
| `BLOCKED` | A named external decision is missing. |
| `NOT_APPLICABLE` | The project has no such component or lane. The reason is cited. |
| `SDK_CHECK` | Verified against the 3.47.5 source before use. The file:line read is recorded. |

`CONFLICT` and `BLOCKED` entries are never implemented, and no gate, test or fixture may assert a spec value that one of them rejects, without the owner's signoff. A mixed row names each part's class. Component-level verdicts are in section 4 (compliance matrix) and section 5 (findings M3F-nn); a row that still needs one names the finding or the owner question.

Enforcement names used below (all implemented): `tools/m3_lint` rules `M3L00` (stale allowlist entry) and `M3L01`..`M3L08` (DEV-381); `test/app/m3_production_theme_test.dart` and `test/app/m3_overlay_barrier_test.dart` (DEV-382).

## 5. Findings by root cause

Method. Six read-only category audits ran first (theme foundation, chrome and navigation, actions and selection, inputs and forms, overlays and feedback, lists and surfaces). Their 37 candidate findings were not copied. Each was re-verified here: the cited code and SDK lines were read, every contrast figure was recomputed from `design/tokens.json` with the WCAG 2 formula, and every claim about rendered behaviour was run as a probe, a throwaway widget test under the production theme (`buildLightTheme()`, `buildDarkTheme()`, or the real `MemoxApp`), deleted before the commit. A candidate that did not survive is in 5.3 with the reason; one that could not be proved is in 5.2 and is not a finding. 25 candidates were confirmed and merged into 19 findings in 9 root-cause groups. The owner's ruling of 2026-10-15 then reclassified one of them, M3F-01, as the conflict M3C-52 (its id is not reused), which leaves 18 findings in 8 groups (B to I). 3 other candidates became conflicts (M3C-32, M3C-49, M3C-51); 4 stay unverified (5.2); 5 were dropped or were gate gaps.

Class. Every finding is `ADOPT`: a rule that binds the project (the spec row where the ledger says ADOPT, or an approved source such as `PRODUCT.md`, `DESIGN.md`, `design/tokens.json`) and that the code contradicts. `CONFLICT` and `BLOCKED` items are in sections 2 and 6.

Severity. It follows `references/workflows.md#severity` and the controller ruling of 2026-10-15: it reflects the verified defect, and a missing state test alone is `UNVERIFIED` coverage, never Critical. Major: a rendered colour role, contrast or state that the spec or an approved source fixes is wrong on a path a user reaches by touch or with a screen reader, with no equivalent cue left. Minor: the same on a path only a pointer or keyboard reaches while another cue remains, a latent hazard with no violating consumer today, or an optical or consistency deviation. There is no Critical finding: no overlay bypass, no missing scrim wiring and no scrolled-under failure exists (sections 4.7.1, 4.7.2).

Order. By spec §6 priority: accessibility and interaction (groups B to D), tokens and themes (E, F), states and variants (G, H), layout and consistency (I). Within a group, by severity. The failing test named in each finding is the test the FIX task writes first; where this audit already ran its probe, the observed values are quoted.

Totals: 18 findings, 7 Major (M3F-02, -03, -05, -08, -10, -12, -15) and 11 Minor; 0 Critical. Owner rulings of 2026-10-15 that changed findings are cited in M3F-02, -03, -05, -10, -12 and -17.
