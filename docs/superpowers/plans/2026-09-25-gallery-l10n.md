# Gallery Strings in ARB Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every user-visible string in the debug gallery (`lib/app/gallery/`) into the ARB files, en and vi, and put `lib/app/` under the guard's literal-string rule. This closes FE-C7, register §9 row 19.

**Architecture:**
- **Keys:** `gallery…`, each with a description starting "Debug gallery:".
- **Access:** the gallery reads them through `context.l10n`.
- **Guard:** the i18n rule `memox.i18n.no_literal_user_string` moves from `ui_surfaces` to a new scope `ui_copy_surfaces`. That scope is `ui_surfaces` plus `lib/app/**`, so the colour and radius rules keep their scope.

**Tech Stack:** Flutter gen-l10n; the vendored guard's project registry.

**Spec:** `docs/superpowers/specs/2026-09-23-flutter-ui-base-design.md` §9 row 19; `docs/wbs_FE.md` FE-C7; owner decision (popup, 2026-09-25): all of the gallery's strings go to ARB.

## Global Constraints

- **English values stay byte-identical** to today's literals. The gallery golden (`test/app/goldens/app_gallery_*.png`) must stay unchanged in the Linux container.
- **ARB rules:**
  - `test/app/l10n_test.dart` requires a description and a non-empty Vietnamese value for every key, and the same key set in en and vi;
  - the guard warns on a key without a description.
- **Out of scope:** sample *data* that is not user copy stays in code, e.g. a deck name typed into a demo field's controller, or `'1/12'`. Only strings a person reads as UI copy move.

## Review Focus

1. **The gallery in Vietnamese** renders without overflow in its sections. Pinned in Task 2.
2. **Placeholders.** A key that takes a count or name is a placeholder, not string concatenation. Pinned in Task 2.
3. **The guard now scans `lib/app/`:** app, router and shell code must pass too. Pinned in Task 1.
